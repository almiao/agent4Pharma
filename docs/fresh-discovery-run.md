# 清空运行数据后完整重跑

仅在用户明确授权清空全部采集内容及关联分析时执行。保留来源、机构、期刊目录、采集计划及已发布粗筛/精筛规则；不保留旧资料、采集游标、粗筛缓存、情报评估、候选、制作或调查数据。

## 重置

1. 确认没有采集或精筛工作进程正在写入，停止本地工作台，取得采集和精筛目录锁。
2. 使用 `ArchiveBatchRepository.backup` 保存一致 SQLite 快照。
3. `DiscoveryResetRepository.build_clean_database` 从快照只复制明确白名单配置，重置来源访问额度游标；验证运行表为空、外键和库完整性。目标文件存在时拒绝覆盖。
4. 将旧库、WAL/SHM 和 `artifacts`、`workbench`、`paper-downloads`、`regressions` 原件目录归档到本次备份下。每个源和目标绝对路径必须留在已核对的数据/备份目录，不能跟随链接越界；切换失败恢复已经移动的文件。
5. 用已验证的新库替换活动库，保存清理清单，再启动工作台。备份及历史报告不自动重新导入，模型运行环境、权重、凭证和软件目录不在清理范围。

## 重置后的执行边界

2026-11-07 已移除历史专项全量复采脚本及旧逐篇精筛执行指引。底层重置适配器保留，不因脚本清理执行数据库重置。

新采集与筛选使用正式工作台的日常执行入口，按当前来源启停及冻结配置运行；不为一次重跑绕过暂停计划。论文筛选使用本地 Decider 预选与排序、商业整体比较，再由人工推荐进入采编，见[当前流程](paper-selection-pipeline.md)。

真实联网、模型调用及数据清理分别需要对应任务授权。来源失败、部分完成、成功空结果和模型技术失败保持各自状态；不将旧运行报告视为当前执行结果。
