# 界面与交互设计准则

日期：2026-10-31（Asia/Shanghai）。适用于后台各页面的新建、修改与设计验收。

## 核心原则：以界面结构和交互行为传达产品语义

用户应能通过信息层级、控件形态、状态呈现和操作反馈，理解当前对象、可执行动作及其结果。说明文字仅补充当前决策所必需的信息，不承担页面导航、功能组织或交互设计的职责。

## 执行规则

- **结构表达关系。** 用导航、分组、位置和层级区分运行、配置与维护；不以介绍职责的段落解释页面归属。标题对应实际内容集合或任务，避免连续套用近义标题、单子项容器和无实际区分的层级。
- **控件表达动作。** 操作入口放在对应对象附近，名称使用明确的业务动词；可编辑内容使用表单，只读内容使用数据展示。不能操作时，在相关控件旁按需呈现具体原因和可行下一步。
- **状态表达进展。** 用状态标识、进度、数量和结果呈现真实业务状态；颜色须配合可读文本。未知、空结果、失败和未开始分别呈现。
- **反馈表达结果。** 加载、成功、失败与校验反馈紧邻触发位置；错误说明原因与恢复动作，空状态提供适用的下一步，避免只留空白。
- **说明按需出现。** 删除常驻的页面介绍、角色职责、流程讲解、内部实现说明及重复提示横幅。复杂规则置于相关字段帮助、详情展开或帮助文档，避免把整段说明搬进默认展开的卡片。
- **保留决策必需的文字。** 字段标签、单位、操作后果、费用授权、不可逆确认、错误原因和必要的范围限制应在决策发生处清楚呈现。精简说明不得删去可访问名称，也不得把关键信息只藏在悬停提示中。

## 来源目录示例

移除“来源目录只读展示。来源维护 Agent 负责调查入口并提出具体变更建议，人工在来源维护页确认或拒绝”的说明横幅。来源目录以表格展示，搜索与来源调查入口置于表格工具栏；变更建议的确认与拒绝由维护页面上的实际控件承接。

采集计划直接展示计划列表；不在列表上方介绍目录与计划的职责划分，不为只有一个列表增加“已登记计划”的重复标题与额外布局层。

导航已标识当前位置时，来源页直接以搜索和筛选工具栏进入工作区，不再叠加“返回运行 → 来源与采集 → 来源目录 → 搜索来源”。保留辅助技术可读的页面标题与控件名称。搜索框使用明确占位提示；筛选控件默认显示筛选维度，选择后立即生效，并提供重置、分页和结果反馈。

来源目录分别筛选采集可用性、实际来源类型和关注状态。未复核不归为不可用，暂停不归为不可用；组合条件应用于完整目录后再分页，不能仅对已加载的前 200 条做筛选。

## 验收问题

- 移除介绍段落后，用户能否从界面找到对象、辨识状态并执行下一步？若不能，优先修正结构与控件。
- 每个标题、分组和容器是否建立了必要的信息关系？没有独立含义的层级应合并。
- 每段常驻文字是否影响当前判断或操作？仅解释设计意图、角色分工或实现方式的内容应移至项目文档。
- 加载、空结果、失败、未知与禁用状态是否仍有明确且可访问的反馈？

2026-11-04 工作台层级补充：侧栏已标识当前节点时，不再叠加跨全页的节点大标题和职责小字。准确对象由内容中的文档标题表达；全局操作留在顶栏，范围选择靠近对应集合，语义页面标题为辅助技术保留。
