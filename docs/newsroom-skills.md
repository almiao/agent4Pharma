## 主编选题判断与任务书

newsroom-v66 的选题技能直接使用节点上下文接口：`get_stage_context` 入场、`list_task_sources` 查来源、`list_research_items` / `read_research_item` 恢复背景条目、`get_task_checkpoint` 取得写游标。选题技能不再依赖旧整包入口的文本转换；已发布旧资源仍由契约适配器处理，历史冻结任务不改写。完整接口边界见[节点上下文运行契约](production-context-contract.md)。

newsroom-v64 将共同编辑判断集中在 `standards/news-signals.md`：事实与证据约束下，以报道目标决定材料组织和阅读效果，修改成本不覆盖质量判断。主编交接重要认识与依据，作者选择材料和结构；阅读评审诊断具体理解影响，关闭条件不强制某种写法；返修按成因决定范围，复核以当前稿件效果为准，允许有据纠正无效建议。事实核验只核对实际主张与核心承诺，图文保持内容主次。

采编信赖论文内容作为研究报道依据，保留期刊名称和团队归属，不调查、判断或交接接收、上线、刊发状态及出版流程日期，任务书与正文不加入这些信息。阅读评审和事实核验不检查发表状态，不据此补查、阻断或返修；核验聚焦忠实转述，不审查论文科学真实性。此规则替代旧 v36–v47 的公开状态调查与交接要求。

角色入口、结构设计、自审、提交检查与运行时追加指令按职责去重，不预设贡献类型、固定章节或单篇案例。保留现有字段、阶段、工具、准确版本和返修额度；共享规范通过已有技能白名单与必读机制冻结。新任务使用新版资源，继续与重试复用原快照；文件修改不证明常驻进程已切换，离线检查不证明真实生成质量改善。

## 读者解释与段落质量

作者在同一任务里根据读者的理解顺序组织材料，不照底稿逐项扩句；重要数字须说明用途和比较关系，必要限定放在相应结果附近。中文规范v5负责句段与媒体声音，structure-design负责内容取舍，reader-explanation提供原创假设正反例，结构设计、解释示例和最终检查在新作者任务中列为必读，自审查具体理解缺口，final-check查简化后的参照/分母/集合关系。内容提示词不再固定引文条数或要求正文逐项回答任务书。

不新增润色角色、模型会话或固定大纲，不以段长、金句数和AI检测分数验收。事实与任务要求保持原校验，风格建议不自动阻断；新版本只供新任务冻结，旧稿及冻结配置保留。真实质量迭代在本地data/reports/writing-quality-20261104记录，每轮区分实际提交、独立核验及人工阅读判断，不将某一题材的改善外推为全题材稳定性。

## 当前流程与分工

主编选题 → 作者研究与写作 → 编辑核验 → 图文制作 → 人工定稿。

- 主编以摘要、下载前入选依据和必要决策背景判断新闻价值、中心问题和角度，不要求前置理解包。必要时只针对会改变立项判断的疑点读正文。
- 作者围绕question/angle理解论文与调查解释背景，保存作者研究底稿后在同一任务中组织文章、起草和自审，再submit_draft。
- 编辑核对准确稿件的事实、范围和任务要求，接收作者底稿与真实来源；风格偏好只能建议。
- 图文制作选择绑定原图，宿主生成本地渠道包，不改定稿、不冒充外部发布。最终由人工定稿。

论文理解与背景调查是阶段内按需方法，不是固定前置节点或独立Agent。paper-understanding技能保留为作者理解不同贡献类型的方法，不再提交understanding v2。

## 作者研究保存点

主编和作者另外用save_background_research保存可审阅的背景调研中间文档：具体问题、为何影响本篇、答案与准确出处、剩余缺口处置、实际范围和是否足够的自评。可先存计划再更新，同内容重试幂等，追加版本不改冻结输入；同一任务继续，不新增Agent或人工审批。已足够时可零问题，须说明理由；不以条数、搜索数或来源数认定充分，不将未来科研问题变成背景待办。文档通过context.background_research传下游，旧任务缺失不补造。后台任务产物页可查看各阶段文档、历史版本及准确原文，并下载Markdown。

契约由modules/content/writing_research和research_contracts拥有，用例在workflows/writing_research。

save_writing_research保存：对中心问题的回答、论文事实及连续引用、已支持背景、未决问题及省略/限定/核心阻断处置、实际研究范围。宿主绑定准确任务书身份和问题/角度，按expected_version追加版本，同内容重试幂等。

保存底稿不结束任务、不排队新模型任务、不等待人工确认、不修改初始输入。get_production_context返回最新底稿；继续/重试和返工复用保存点，不承诺模型会话中途无损续接。交稿须有准确任务书底稿且无核心阻断，随后随稿传编辑、返工和发行。后台任务产物页可读底稿、历史版本和准确引用，底稿保存不能显示为稿件完成。

已有答案须消解进底稿；只有影响报道事实或核心表述的问题才保留。不把其他患者、原代细胞或临床推广等未来科研问题自动变成采编待办。核心角度不成立时报告明确阻断，当前没有自动重定选题工具。

## 阅读、搜索与证据

摘要和已有证据足够即可使用。正文默认定位单页，确需相邻上下文时最多三页，不为全面性遍历PDF、不独立复现或评审科学有效性。

主编与作者有界使用DSH原生web_search：每查询最多5结果、每条800字符、60秒，最多尝试3次为行为预算，总任务硬时限不变。编辑与发行不获得搜索权限。足够时零搜索；搜索片段经实际callId登记为web_search_snippet，再按真实证据ID读取引用。网页只支持背景，不替代主论文结果；标题不能冒充实质背景核实。未读、未查到与技术失败分别记录。

## 技能资源与公共规范

绑定主论文用于报道其内容。外部背景的出处、转引关系和支持范围由背景调查按需核对。稿件是否忠实转述由事实核验判断。

宿主加载catalog选择角色profile，每次任务冻结目录、正文与hash；DSH先发现技能，按需read_newsroom_resource读取。资料不能授予指令或扩大工具权限。只开放绑定资料、当前租约、明确角色和有限额度；网络与模型执行在事务外。

目标读者、科研证据及中文表达在公共规范页编辑/发布，写作与编辑另读中文表达，作者必读humanizer。主编确定唯一角度和可选边界，作者提出研究问题并决定细节和结构。

acceptance须从本篇question/angle推导，写成读者能够解释的具体变化及意义、能够区分的证据与推断，不重述angle中的数字、方法组成、候选排名和实验结果。事实罗列齐全不代表兑现主线，作者可自行选择支撑细节。标准稿1200–1800字仅供参考，不是上下限；不把默认字数、小标题数量或开头段落位置写成验收门槛。只有输入明确注明来源的人工或渠道硬限制才按硬要求执行。选题、写作自审与编辑使用同一语义；新规则只进入新快照，旧任务书和产物不改写。

公共规范经parent_task_id继承，避免同一篇文章中途切换标准。准确继续/重试复用冻结任务配置；本次不提供旧理解链执行兼容，用户允许的历史清理单独备份和记录，不在启动时静默清库。
