# 摘要筛选与个位数全文清单

资料采集 → 主题初筛 → 价值排序前 10 → 整体比较给出最多 5 篇下载建议 → 人工推荐并关联主文 → 稿件制作、审稿及交付。

## 已处理去重与人工选择

建立新的筛选运行时，按正式下载账本中成功、主文身份通过且有 PDF 哈希和页数的关联记录，
以资料身份、规范化 DOI 或准确来源版本匹配，跳过已关联主文的论文。
新运行保存 `processed_record_ids`，价值排序显示跳过数量；失败获取、未校验文件和调试下载不计已处理。
不按标题或日期猜配。采集资料和旧批次不删除，已冻结运行续跑不改输入，不追溯改写历史名次。

价值排序支持查看归档摘要及原始出处；本轮筛选结束且未暂停后可“加入精选”。
人工选择保存独立的 `manual_selected_at`，不改模型比较结论、名次或自动下载容量，不启动模型。
精选集合合并本轮比较成员、模型建议下载及人工加入项，默认将模型建议下载排在前面。
同轮未获下载建议的论文也开放人工关联 PDF；自动浏览器获取仍限原冻结下载清单。
DOI 提供复制按钮。人工关联始终校验准确来源与主文身份，不能提交任意文件路径。

“仅关联 PDF”只保存主文；“确认推荐并启动采编（会调用模型）”才授权制作。
人工关联后可查看已校验工作副本，不因模型未推荐而阻止推荐和后续制作。
自动获取权限和模型最多五篇建议的容量保持原规则。

只读批次目录以真实发现批次为准，包含采集中、成功空结果及尚无预选判别的批次；
没有预选记录不等于批次不存在，也不代表已经执行模型。默认目录列出最近 50 个批次，
URL 准确指定的历史批次仍可读取并保留在目录中；未知批次 ID 明确报错，不切换到其他批次。

## 整体比较的提示词与输出

在“规范与提示词 → 节点提示词”编辑“价值排序”和“论文精选 · 整体比较”。新运行冻结当前发布版或内置正文、示例、版本身份及目标读者。保存草稿或发布不启动模型。规则变化后按批次启动会另建运行，指定运行续跑仍使用原快照（ADR-084）。

整体比较先逐篇判断主题关联和可引用的新闻线索，再在有选题价值的论文中按机构、期刊和同档新闻价值取舍。每篇保留判断、关联等级和简短理由。新协议的推荐项另给一句新闻点和一处可定位的原文依据；AI、领域及机构分项引用由历史卡片保留，模型无需再逐项填写。机构优先级使用冻结的作者单位匹配结果。下载前问题由旧卡片保留。

旧逐篇摘要复核、全文终判及其执行入口已退役（ADR-083）。单纯关联 PDF 不启动模型。人工通过“确认推荐并启动采编（会调用模型）”确认后直接交接采编，推荐绑定准确的来源版本及主文 ID/SHA（ADR-067）。

## 当前优先级与RSS单位（ADR-048，paper-news-v2）

商业JSON比较另按ADR-049显式冻结非思考模式，避免4096输出额度全部消耗在思考、没有可校验JSON；不增加输出额度。旧请求缺此字段保留provider_default，旧失败运行不换参数续写。

ADR-050区分有选题价值与本次下载容量：recommend可以多于5篇，selected_ids最多5篇且必须全部来自recommend，其余有价值论文容量延期。冻结池每篇都须返回判断，所有 recommend 都必须有实质关联、新闻点和可校验的本篇原文引用；原始模型判断和程序容量说明分别保留。

基本主题相关作准入门槛；新闻优先级依次是明确单位命中本轮关注机构、高影响力期刊、有新闻价值的新方法/进展，最后才看主题关联程度。机构名单及别名随运行冻结，可在 news_preferences 查看初始编辑关注名单；未命中不代表低质量，未知单位不触发补取或排除。重点期刊之外的普通期刊、预印本、未知载体同档比较新闻价值。

本地程序先按机构、重点期刊分组，同档按独立新闻logit差选前10；商业整体比较最多5篇后，程序按机构、重点期刊稳定排序，同档保留商业顺序。保留原始商业输出与最终条目名次，不能把自由文本机构声称当作已匹配的机构信号。仅相关但没有具体新闻线索时仍可不推荐。

RSS-v3提取明确条目级XML/Atom作者单位、作者单位属性和有明确标签的HTML单位，保留字段路径和原文。不把频道、出版商、作者姓名或正文中提到的机构当作作者归属，不宣称逐作者对应。新采集 metadata.affiliations 经 selection_details 进入排序，未知留空，不额外抓论文页面或PDF。采集快照额外冻结 feed_parser_version，旧批次不可静默更换提取器。paper-news-v1及旧排名只读保留，按批次启动新版建立独立身份。

只读真实检查：当前71个启用RSS入口中70个成功、1697条目均无明确单位字段，另1个读取失败；因此当前RSS通常仍由期刊与新闻价值决定先后。详见 data/reports/rss-affiliations/audit.json；不代表未来Feed永远没有单位。没有运行真实模型比较。

## 第一版新闻筛选（ADR-046，历史paper-news-v1）

新运行冻结 `news_selection_version=paper-news-v1`，主题相关只作门槛。沿用重点期刊、其他已知期刊、预印本、未知载体分组，同组本地独立原生 logit 问题比较新闻潜力：具体新变化、重要瓶颈、读者意义与相应证据。大机构大厂仅在实际作者单位或原文支持时加分；缺失单位保持未知，不能凭姓名或出版商猜测。PubMed 单位从采集字段或已归档 XML 离线恢复，不额外取全文。

固定前10后商业模型一次横向比较全池，返回逐篇理由、新闻线索、依据与全文待核实问题，按新闻价值选最多5篇（允许少选或零选）。最终顺序由商业比较给出，不按关联等级重新覆盖。相似新闻角度避免重复占位，但不将所有同主题论文视为同一事件；作者自述突破不视为已核实事实。现有精选名单的入选理由展示这些信息。

完整比较输入、提示词、模型身份、额度及结果随运行保存。程序校验逐篇覆盖、池内身份、引用、主题门槛和容量；网络、协议、截断或校验失败保留断点，不生成名单、不扩池。每次一次HTTP请求，最多两次后须显式重试。商业比较无工具调用，不取正文/PDF、不生成主编候选，只有人工下载后才进入既有全文流程。

按批次启动筛选会为旧池创建独立新版，复用摘要并重算本地判断和排序；指定旧运行ID只允许历史查看，不用新规则续写。旧运行和历史任务不改写。本轮只做离线验证，新闻价值质量仍需另行授权真实模型对照评估。

## 阶段边界

`abstract` 阶段的 MCP 只注册绑定输入、摘要工具和提交判断；用例也拒绝正文／下载调用。`priority_relevance` 为 0–3 的关联程度及理由，只有 2／3 可通过。摘要推荐不写正式候选，技术失败不转业务排除。

摘要任务不携带全套历史候选卡片，避免把轻量关联判断变成大上下文调用；原历史仍冻结在运行中供全文阶段使用。

整个冻结池摘要结束后才固定清单。初版按明确的重点期刊白名单、其他已知期刊、预印本、载体未知分组，同组按关联程度降序，最后按来源 ID 稳定排序。白名单是编辑偏好，未知载体不代表低质量；Decider 概率和旧关键词不当作价值分。默认 `paper_shortlist_limit=5`，程序仅允许 1–9。未进入清单记 `deferred`，保留摘要结论；下载失败不会从池外不断补入，续跑不扩大全文量。

同一 material_ref 多来源选原生摘要更完整的快照，原来源不删除。未实现全量跨版本、跨新闻的研究事件聚合，不能宣称语义去重完备。旧 PubMed 缺期刊时从已归档 XML 离线恢复，不改原始资料。

首次显式推进另建独立运行，冻结当时发布准则、批次模型／地址／token 配置、阶段正文、期刊白名单和容量。`data/paper-selections/selection-*/<revision>.json.gz` 由 discovery 专用仓储在工作锁内比较版本、原子追加；未变状态不追加。没有数据库迁移，不改历史判断或旧任务默认序列化 hash。

存储 v2 对重复准则、阶段指令和历史使用精确内容引用，读取还原同一任务输入；早期直接 JSON 格式仍可读。本机 1,578 项运行的新版快照约 1.54 MB，旧版约 67.25 MB，旧版本未删除。

## 下载与人工接入

ScanSci 运行适配器、进程及批量探测脚本移除，历史下载与账本保留。默认获取改用用户日常 Chrome 的 Chaoslib 页面，经官方 Playwright MCP 扩展连接，不承诺站点稳定。

- 每轮最多两篇尝试；账号默认不限每日尝试次数，按 UTC 日保留计次，间隔至少 120 秒；出版商入口、正文和 PDF 动作之间至少 30 秒。页面就绪、即将打开出版商时才占次数，之后失败也计次；等待扩展连接不计，重启不重置历史。这里计的是获取流程，页面加载可能产生多个 HTTP 请求，不能称为严格 HTTP 限流。
- 默认路径不读取 `PAPER_D_ACCOUNT`／`PAPER_D_PASSWORD`，复用用户选定标签的登录状态，不复制 Cookie、不读浏览器存储、不改远程调试设置。旧 `chaoslib`／`login` 命令仅保留为显式诊断入口，不被工作流回退调用，暂停继续生效。
- 日常浏览器需要用户预先登录；遇到验证、入口维护、登录失效或未知跳转直接转人工，不提交口令、不解验证码、不自动重登。只操作绑定 Chaoslib 标签和本次新开的出版商页。
- 初版自动步骤支持 Nature（10.1038）与 Springer（10.1007），其他出版商直接人工待办；已知域名校验不等于已证明所有代理页面 DOM 兼容。
- 限流冷却至少 30 分钟，认证失败一小时内不自动重试。封禁为人工锁定，过 24 小时也不会自行恢复。人工确认恢复只清本地暂停，不清当日次数，不证明服务恢复。
- 获取失败、人工认证、无入口／权益分别留档并让路。只有显式重试才重新请求受阻条目。人工取得主文可按运行／来源版本导入。
- PDF 主文身份、附件边界及文本校验通过后才分析；全文工具消费前再核对 PDF／文本双哈希。工具只读取宿主准备的绑定文件，不重复联网。
- 全文未准备好时不启动终判，程序也拒绝模型把下载未完成提交为证据不足排除。取得正文后才按证据、主题、编辑价值终判并交正式候选。
- 每项摘要／全文模型技术失败最多自动尝试两次，之后需显式重试。人工待办与容量延期不会让调度持续重试。

## 命令与 DSH

### 人工下载按钮

精选名单作为默认首个页签始终存在；未生成时显示本批次摘要完成数、剩余数及进入「摘要筛选」的按钮。进度只读叠加同一 selection_ref 的已提交任务，不等整批快照保存；每 15 秒刷新，不将进度投影写回排序或提前开放下载。下载控件未满足条件时显示原因。

当前连接接口为 `POST /api/paper-downloads/connect`（只接受空 JSON）和 `GET /api/paper-downloads/connection`。POST 仅触发当前运行台连接／检查，GET 只读状态；两个接口都校验工作台令牌。连接状态和当次备用地址只在内存中保存。原始诊断通过内存管道过滤，不写浏览器日志文件；断线事件及时撤销就绪状态。

常驻版本现场验收：用户在页面确认「浏览器已就绪」后，连续两次正式 HTTP 检查分别约 0.83、1.08 秒返回 `ready`，没有新的待确认地址，账号账本完全未变，登录提交与 PDF 尝试均为 0。记录见本机 `data/reports/chaoslib/persistent-browser-checks-20261101.json`。此前用户授权的额外单篇验收停在三分钟连接等待，未进入出版商；该失败历史及原计次保留，未自动重试，不能把常驻连接验收称为 PDF 下载成功。

运行台「情报筛选 → 精选名单」中，进入个位数全文清单的论文在列表及详情显示「下载 PDF」。摘要未完成、未入选或容量留存不出现此按钮。打开窗口后点击「开始获取 PDF」，只下载本篇，不启动模型。已有已校验 PDF 时直接「保存已校验 PDF」，不重复访问站点。

先在列表上方点击「连接日常 Chrome」，在扩展页确认并选择已登录的 Chaoslib 页；页面显示「浏览器已就绪」后再下载。连接由当前运行台常驻持有，后续论文复用，不需要每篇复制地址或重新确认。授权等待最多十分钟；自动弹页失败时，「未弹出连接页？」内有当次备用地址。浏览器关闭、连接断开或运行台重启后需要重新连接；独立 CLI 不共享运行台进程的连接。

窗口显示已受理、获取、主文校验及成功／人工待办状态。关闭窗口后本次任务仍继续，可再次打开查询；不会因为刷新页面开始新下载。下载不隐式新建连接；未就绪先连接，状态读取失败只刷新查询，不新增下载任务。

暂停时需在窗口勾选“确认账号恢复，解除本地暂停并仅尝试本篇”；这是人工恢复确认，不清每日次数。失败只有点击「重试 PDF」才新增一次尝试。默认不限每日次数、保留至少 120 秒间隔，同一时刻只运行一篇；不支持的出版商和未通过验证的文件转人工导入。

`POST /api/paper-downloads` 只接收 `run_id/record_id/retry/restore_account`。`GET /api/paper-downloads?run=...&record=...` 仅查询状态，`GET /api/paper-downloads/file?...` 在同源令牌和文件哈希校验后返回 PDF。界面下载任务存于 `data/paper-downloads/jobs`，原逐次尝试账本不覆盖。连接地址不落盘；重启后未完成任务最多十分钟转中断待办，无自动重试。获取完成会将准确条目恢复到可全文分析状态，但不自动调用模型。

离线集成测试使用可控浏览器替身和实际生成的 PDF，验证本地 HTTP、权限、重复提交、主文身份、哈希与人工重试。没有用这些结果代替真实 Chaoslib／出版商下载成功率；当前真实池仍需摘要筛选结束后才会出现可下载的精选条目。

```powershell
uv run pharma paper-selection --batch <批次> --abstract-budget 30 --download-budget 2
uv run pharma paper-selection --batch <批次> --abstract-budget 30 --download-budget 0
uv run pharma paper-selection --batch <批次> --status
# 准备锁定运行库；不会安装扩展或访问 Chaoslib
uv run pharma paper-download browser-setup
# CLI 独立诊断：单次会话，不与运行台常驻连接跨进程共享
uv run pharma paper-download browser-status
# 可选：为已进入全文清单的一篇论文生成 DSH 配置，不启动模型
uv run pharma paper-download browser-config --run <selection-ID> --record <source-record-ID>
uv run pharma paper-download import --run <selection-ID> --record <source-record-ID> --file <主文PDF>
uv run pharma paper-selection --batch <批次> --retry-downloads
uv run pharma paper-selection --batch <批次> --retry-models
# 仅在人工确认账号实际恢复后解除本地暂停，不联网、不下载
uv run pharma paper-download account-restored --confirm
```

`screen` 和日常入口共用此链路；旧批次底层计数仍保留，不把容量留存伪装成已完成全文精筛。运行台「精选名单」合并冻结入选、同轮比较及人工加入项，「价值排序」保留完整池及逐篇状态；正式精筛指标排除摘要任务。

DSH 情报沿用受限 `intelligence-mcp --task ...`。宿主把 `agents/intelligence/abstract_selection.md` 与 `fulltext_selection.md` 冻结进任务，实际执行时拼入指令。MCP 工具集合和用例校验共同限制阶段，模型无账号维护、任意路径、清空额度或解除封禁权限；人工导入与恢复归 CLI 明确入口。

获取角色使用 `agents/intelligence/browser_acquisition.md` 和独立 `browser-paper-mcp --root ... --run ... --record ...`，只暴露无参数的 `get_browser_paper_status`、`acquire_browser_paper`。启动时拒绝摘要阶段或清单外论文，失败也缓存，重复调用不重试；正式分析仍由后续情报任务完成。DSH 配置关闭通用 Shell／文件工具。宿主内部静态浏览器脚本不接受模型或页面指令。

[官方扩展接入说明](https://playwright.dev/mcp/configuration/browser-extension)与[Chrome 商店安装页](https://chromewebstore.google.com/detail/playwright-extension/mmlmfjhmonkocbjadbfplnigmagldckm)。安装扩展及连接日常会话需要用户确认；Codex 自身的浏览器连接不能直接转交给 DSH。npm 运行库和依赖树锁定于 `infrastructure/web/browser_mcp_runtime`，运行文件位于忽略目录 `data/tools/browser-mcp`，不会自动升级或启动新 profile。

## 本轮真实验证

两篇 Nature 系论文下载均未取得 PDF，独立浏览器入口诊断返回认证／访问拒绝；用户反馈封禁后已停止相关进程并记录人工锁定。随后用户确认日常 Chrome 可登录，Codex 在用户选择的已有标签验证了菜单可见；独立浏览器再试仍显示封禁。具体风控原因尚未证实，不能称账号全局不可用。原本地暂停仍保留，未自动清除。

日常浏览器路径已完成固定脚本、绑定 MCP 和离线失败恢复测试；真实 stdio 初始化不连接网站。扩展安装／连接及真实单篇 PDF 获取仍需用户确认后验收，不能将这些测试称为下载稳定性验证。

扩展安装后首次真实连接检查：本地 stdio 和扩展中继已启动，但未收到扩展回连，用户未见连接页；当时项目所在 Windows 未检测到 Chrome 进程。未访问 Chaoslib 或下载论文，不能将此现象归因于站点封禁。页面状态检查最多等待 60 秒后返回固定超时原因；需在同一台 Windows 的日常 Chrome 中安装扩展并保持运行，跨机器浏览器不能通过本地中继自动连接。

后续手动连接日志证实扩展已回连，但浏览器初始化在创建系统临时目录时失败（`EPERM / mkdtemp`），中继随后关闭，扩展显示 WebSocket error。已用同一 Node 验证原临时目录失败、项目目录成功，并仅为 MCP 子进程覆盖 `TEMP/TMP/TMPDIR` 到 `data/private/chaoslib/browser-temp`；不改系统环境、不继承文献口令。独立拉起 Chrome 的异常退出尚未解决，手动连接仍在验收，不能将临时目录修复称为完整浏览器接入成功。

随后定位到第二处权限错误：Playwright 连接登记缓存 `LOCALAPPDATA/ms-playwright/b` 也不可写。Windows 子进程的 `LOCALAPPDATA` 仅对该进程改为 `data/private/chaoslib/browser-cache`，同时通过官方 extension 模式的 `--user-data-dir` 显式传入原来就存在的日常 Chrome 数据目录；目录不存在则失败，不创建独立 profile，不复制会话、不修改系统变量或权限。Node 实测覆盖临时目录和连接缓存均可写；扩展真实页面状态仍以现场返回结果为准。

两处目录修复后，用户手动授权并选择 Chaoslib 页，实际固定 `CHECK_SESSION` 返回 `ready`；登录提交和下载尝试均为 0。运行库会在 stderr 给出当次本机确认地址，自动弹页失败时可复制到已有 Chrome；链接只在该会话等待期间有效，不含免确认 token。原始连接诊断仅存临时私有文件，退出删除，不把原文交给模型。此验收证明已登录页面可访问，不代表 PDF 下载成功；原账号暂停和尝试额度未清除。

离线验证不能证明下载稳定。未运行全池真实 LLM，未完成跨日成功率、封禁恢复、Elsevier 等出版商人工验证后会话复用验收；这些路径保持人工待办。


### 人工单篇下载调试（2026-11-01）

用户要求暂停后台筛选、先自行调试 PDF。精选与全文页提供独立的「单篇 PDF 调试」，从已登记论文中选择；不要求摘要已完成，不伪造精选排名。
调试调用 `/api/paper-downloads/debug`，只接收绑定运行与记录 ID，仍需同源令牌和浏览器已就绪；复用现有单篇执行、账号尝试间隔与暂停机制、间隔、文件校验和人工重试。
尝试身份前缀为 `debug:`，与正式全文任务隔离，结果不写回精选状态，不调用模型；可保存通过校验的 PDF。调试和正式入口共用浏览器、账号和全局单篇任务锁。


出版商确认页接管修正：下载脚本优先复用与已授权 Chaoslib 页具有直接或二级 opener 关系的已打开 Nature/Springer 页；若尚无可用页面，只打开一次出版商入口，最多等待 60 秒供用户手动确认并开出新页。脚本不点击人工验证按钮，不读取无关标签正文；多个同类可用页面交人工选择，保留人工页面。此修正有离线二级新标签测试，尚未证明真实站点下载成功。

代理文章路径返回 HTTP 404 时单独报告 `publisher_article_not_found`，保存状态码，不归为缺 PDF 按钮或反爬。Nature 单篇窗口提供官方原文链接供人工核对，不自动变更代理路由。


## 当前本地摘要与前十复核（替代早期全池商业摘要流程）

`screen_batch` 默认只走 `local_decider_v1`，配置未启用本地模型时直接报错，不回退云端。旧运行不修改，新运行重建本地判断；每16篇保存模型输出、摘要出处及本地排序分值。
本机固定 Decider 原生 `logits()` 可用于排序；本地 `/rank` 只接受文本 `priority` noul 问题，按 `[false,true]` 原始值计算 `true-false`，严格校验身份、结果数和有限值。排序问题独立于分类问题，不使用分类概率代替阅读价值分。
全池本地阶段结束后固定前10供商业模型复核；商业调用复用受限摘要角色及原有结构化证据校验，最多五篇进入全文清单。复核不访问正文，不生成主编候选，不自动下载；失败待显式续跑，不扩充前10。
本地来源缺摘要单独显示待补，不冒充排除；上游摘要技术失败和排序服务失败保留断点。只有原生摘要或实际补取证据可输入模型。
2026-11-01 本机 RTX 4080 首批真实16篇摘要与13篇通过项排序耗时8.23秒，未调用商业模型；不代表全池耗时或模型质量已校准。


## 无摘要正常处理（ADR-044，替代早期待补摘要分流）

当前运行 `missing_abstract_policy=best_available`：摘要确实不存在时，模型输入为标题和已有来源文本，`information_status` 准确标记 title_only/source_text，不能制造摘要字段。正常得到分类和排序结果，不进入待补摘要业务队列。
商业复核提示明确“缺摘要本身不是排除理由”，`abstract_checked` 防止重复补取已知空结果；旧请求省略该新默认字段以保持旧任务身份不变。旧运行与待补状态只保留历史，不回写历史输出。


## 人工下载确认与多目录匹配（2026-11-02）

确认时同时检查项目 `<data_dir>/paper-downloads/inbox`、Windows登记的下载目录（支持重定向）、用户常规Downloads，以及Chrome标准User Data下Default/Profile配置中的download/savefile.default_directory。目录去重，不启动或连接浏览器，不读取下载历史、账号或凭证。无需搬动、重命名文件；「检查目录」展示宿主发现的位置。自定义Chrome用户数据根目录目前不自动发现。

`POST /api/manual-pdfs/confirm` 只接受冻结运行、记录ID、可选文件令牌和 `recommend_and_start`，拒绝任意路径和运行外论文；本轮筛选完成后，人工关联不受模型下载名次限制。每个目录只检查最近50个完整PDF，不递归扫描；排除临时文件、目录外链接及超过100MB文件。按PDF首页主文身份匹配，不用文件名或最新时间代替匹配。

唯一匹配复制至项目 `paper-downloads/manual` 后再次校验主文及哈希；多个匹配显示文件名和来源目录，由人工选择。同名文件令牌包含绝对位置、大小与修改时间，目录不同或文件变化不能沿用。原文件保留；扫描不产生旁路文本。目录或Chrome偏好读取失败明确显示警告，其他目录继续检查。

接口保留directory兼容字段，增加directories/warnings及候选directory。单纯文件关联不授权模型；recommend_and_start=true才确认人工推荐并交采编（ADR-067），不执行获取后的推荐复筛。

## 关联成功后的自动推进（ADR-045）

仅关联不授权模型；显式确认推荐并启动采编才授权本篇后续的有界模型流程。原PDF留在下载位置，工作副本与首页身份核验文本放在manual目录；人工推荐后直接进入主编选题及后续制作，不恢复下载后全文终判。支持本地发行预览，外部交付另按准确人工批准包执行。
关联不会改写模型比较结论；进度和文件获取单独保存与显示，旧全文判断只读保留。查看原文读取已校验工作副本，不打开未关联的inbox候选或外部路径。失败留待办，刷新不重复执行；后台排队与执行可从顶栏入口查看。


## 原文按需阅读与引用（2026-11-01）

关联成功只提供文档身份、页数和已知摘要，不把整篇论文加入 DSH 上下文，不按页预取全篇。论文判断、写作和审核按各自需要显式请求具体页窗（默认一页、最多三页）或已登记证据片段；未读部分保持未知。读取范围与截断、续读信息留档，原文片段不冒充读完整篇。引文可用证据 hash 与字符范围由程序提取，仍接受逐字引用与独立编辑语义核验。详见 [MinerU 接入](mineru-provider.md)。

## 期刊暂停（2026-11-02，ADR-068）

config/discovery.toml的paused_journals用于暂停使用某刊；当前为NEJM AI，原因是用户当前无法获取主文。新运行按明确期刊名称归一匹配，PubMed等间接来源同样跳过，不调用本地判别、排序或商业比较；输入保留为独立paused_items而非主题排除。暂停名单及跳过清单随运行冻结并在轻量投影保留；历史运行和已有人工推荐不改，恢复时在新运行重新纳入。
