# 节点上下文运行契约

本页说明新任务的 `node-context-v2` 及历史 `node-context-v1`。整体目标见[业务设计](production-context-design.md)，拆分依据见[代码方案](production-context-code-plan.md)。代码接入不代表常驻进程已重载，也不代表历史任务自动迁移。

## 生效与恢复

- 新采编根任务冻结 `context_contract`、`context_tools`、提示词及派生技能资源 hash。已发布资源中的旧整包工具引用由确定性适配器转换后冻结，不修改资源发布库。
- 后继继承父任务的上下文契约。历史任务缺字段仍按旧接口工作；未知契约拒绝解析。技术继续/重试不改变原模型、额度、提示词和工具配置。
- 新根任务另冻结 `revision_window_policy`（revision-window-v1），后继继承；仅补丁返修启用活动窗口执行器。历史任务缺此字段时继续使用原行为，不能在重试时补上新策略。
- 新重试任务把前次已提交的研究作为带原任务身份的继承保存点，本任务研究历史从空开始；继承版本与本任务写版本分开。未提交模型内容不能恢复成产物。
- 重试只修改原输入中明确允许变化的父任务和恢复保存点字段，不通过当前模型默认值重建整个历史 JSON。

## 暴露边界

| 节点/入口 | 模型可获得 | 不随入口携带 |
|---|---|---|
| 主编 `get_stage_context` | 候选、入选依据、来源目录、恢复游标 | 全量研究正文、论文全文 |
| 初稿 `get_stage_context` | 准确任务书、来源目录、恢复游标 | 上游聊天、研究全文、历史评审 |
| v2返修 `get_revision_context` | 当前候选正文首6000字符、准确版本、任务书、必改集合/报告身份/范围hash、返修及证据规范 | 引用账本、来源首屏、完整表达规范、研究正文、历史观察；均按需读取 |
| 历史v1返修 | 原冻结工作集：完整稿、引用索引、规范、来源首屏和游标 | 不自动改为候选工作区 |
| 新排队v2阅读评审 | `get_reader_review_context` 完整成稿与冻结必读资源 → `record_reader_observation` 保存观察并开放任务书 → `submit_reader_review`；历史按冻结工具继续 | 作者研究、事实通过意见、来源与研究恢复接口 |
| 事实核验 `get_stage_context` | 完整稿件、任务书、前轮事实报告、来源目录；必要时准确图注 | 阅读报告、作者自评、完整底稿 |
| 图文 `get_stage_context` | 完整准确稿件、图文任务、来源目录 | 研究与评审全文；不开放研究分项读取 |
| 人工改稿 | 原有准确成品与选区接口 | 作者研究与通用恢复接口 |

新契约不注册 `get_production_context`，直接调用该方法也会拒绝，`recovery_only=true` 不能绕过。

阅读评审合并入口由冻结工具清单识别。全文、全部必读规范与案例一次交付，宿主记录已处理资源并返回通用上下文回执。首次观察持久化与任务书开放共用一个工作单元；覆盖观察或读取失败时整体回滚。上下文缺失可重取完整工作集；本任务已有观察时省略record_reader_observation的result可恢复任务书。Harness常规压缩仍生效，专用返修活动窗口的启用范围沿用原规则。三次调用描述正常路径，恢复、历史报告按需读取及异常处理仍可增加交互。历史已冻结工具与继续/重试不升级。

`list_task_sources(cursor)` 每页十条，只含身份、hash、来源与文档信息，不带来源正文和定位符全集。游标绑定整个来源集合的 hash，增量改变集合后旧游标拒绝使用。`list_research_items(cursor)` 每页二十条，按研究字段、事实、问题或骨架段给出目录；`read_research_item(ref)` 只返回一个准确快照条目。保存改变快照后旧 ref 不自动指向新版。事实核验的分项目录排除作者自评和骨架等非事实字段。

`get_task_checkpoint` 只返回保存点身份、写游标、读取额度与缺少的规范资源，不带稿件或研究正文。写作读取和保存共用 `writing_research_cursor`：新契约首次本地修改用 0，上游版本保留在 `current_version/origin_task_id`；历史契约沿原跨任务版本语义，读取返回值与保存校验保持一致。

新MCP契约的研究保存强制使用简短回执。写作回执返回下一次本任务写游标：原样复用继承底稿时仍为0，不返回上游版本号；本地成功写入后递增。关闭 `receipt_only` 也不会让新MCP会话重传整份底稿。业务仓储仍保留完整研究与来源身份。

## 补丁候选工作区（v2）

- 保留原稿补丁协议，不让模型输出完整新稿。`get_revision_context`恢复当前候选，`read_revision_candidate`按body/claims/diff/metadata/history读取；正文与diff每次6000字符、引用每次10条，claims可按原文关键词筛选，返回准确索引和候选版本。
- `edit_revision_candidate(edit, expected_version)`每次最多五处准确替换，保存即生成候选版本。允许编辑中的引用暂缺；不能因此绕过正式稿件结构、证据或审核校验。错误补丁返回明确反馈，不覆盖已保存版本。
- window-v1 的入口增加最多十条与当前问题锚点逐字匹配的旧主张及准确索引；旧主张不是事实认证。`apply_revision_step`一次保存一个问题的补丁、作者回应并返回共同机械预检结果，减少模型往返。预检失败保留候选，补丁无效不保存；预检成功后直接正式提交，事务仍复验。旧分步接口保留用于恢复和复杂编辑。
- `read_revision_candidate(section=issues)`按需展示报告/稿件/hash、开闭问题ID和结论，历史长文不随入口携带。当前问题的origin绑定报告及稿件；不能只凭相同问题ID推断事实问题为同一实例。
- `respond_revision_issue`逐项记录当前必改问题的处理依据；不重新打开已关闭问题，不视为独立审核通过。`restore_revision_candidate(version, expected_version)`恢复明确保存点，0表示原稿；恢复追加版本，不删除历史。
- `validate_revision_candidate`复用正式交稿的结构、研究前置、引用和回应校验；其通过仅表示机械预检成功。`submit_revision_candidate(expected_version)`在正式交稿事务内重新检查候选游标、租约、任务书版本和全部校验，生成正式稿并进入独立审核。v2返修不能绕过工作区直接交整稿或旧补丁。
- 候选由content契约拥有，序列化在当前任务JSON中，记录原稿ID/hash、问题范围hash、版本、保存任务身份、时间和变更理由。最多50次保存，达到上限明确阻断而非覆盖。技术重试显式继承此状态及原始保存身份，新阶段和重做不继承；未经工具保存的模型内容永不作为候选。
- 返修工具集按业务阶段冻结：保留局部编辑、原文、规范、研究分项读取与阻断，不暴露完整研究保存、初稿提交、通用整包或默认网页搜索。多处引文定位保留最多8项的批量入口，共用内容覆盖和额度检查，避免为了减少工具定义而放大模型往返。需要超出绑定资料的核心调查应报告具体阻断，不默默升级为完整研究任务。
- `diff`展示正文变化，标题/摘要/回应看metadata，候选历史看history；通用工具观测保留实际编辑请求、回执及预检反馈，不另造返修专属trace。

## 内容覆盖与重读（v2）

`read_evidence`、`read_document`和`find_bound_evidence`/`find_bound_evidence_batch`共用当前MCP会话的已交付窗口。只有同证据版本，或同一文档hash内的唯一连续逐字匹配才可复用；相同文字但不同来源不互换归属。任意页窗与字符窗重复也能识别，而不仅比较请求参数。

完整交付时使用text；部分重叠时text为空，segments返回新增原文及原始字符坐标，reused返回请求内已交付范围及对应证据位置。它们不是一段连续引用，不能拼接后伪造source_span。`reread=true`显式重读完整请求窗口；新MCP会话重新建立覆盖记录，不能继承“模型仍记得”的假设。window-v1执行器每次替换窗口后同步推进可见代次，MCP在下次交付前清空覆盖；即使只有候选内容被卸载也保守失效。旧任务仍需显式重读。此机制不猜测跨页实验归属、不改写解析原文。

## 来源与提交

新任务来源范围为冻结输入、准确稿件绑定证据及本任务授权取得的增量。`bound_task_evidence` 供目录、读取、研究保存、事实核验与交稿使用；同选题后来写入的其他证据不会自动获准读取或引用。网页/PDF增量经原权限、租约和额度检查登记，网络仍在事务外。PDF产物、任务增量与读取回执在同一业务工作单元提交，暂停后的晚到结果不能写入。

`resolve_active_issue_set` 为返修展示、候选绑定和交稿要求提供同一集合。历史契约沿全历史事实必改规则；window-v1以最近事实报告及最近阅读报告为本轮权威问题单，不把已被后续核验替代的问题永远累加。阅读关闭沿报告顺序处理，后续重新列为必改时不能仍显示已关闭。作者回应不是关闭。范围hash绑定权威报告；旧无关历史变化不作候选内容变化。报告原件始终保留；不根据摘要自动迁移问题身份或放行。

## 活动窗口与全周期成本（window-v1）

- 先做无模型替换：明确有更高候选版本时，卸下旧body/claims/diff/metadata及过期校验反馈，保留任务书、必改问题、必需规范和重新读取路径。工具调用/结果配对不删除，原始事件不改写；替换载荷不沿用旧送达回执。
- 仍有压力时才调用Harness原生压缩事务。默认估算输入达到40,000 token，保留最近约12,000 token并退到完整工具组边界；每次尝试最多一次摘要调用。该阈值是本业务成本策略，不是供应商窗口上限。24,000阈值、两次压缩的实测方案虽减少累计token，却增加非缓存输入和费用，因此不作为默认。
- 摘要可能有损，不是引用原文、候选版本或审核结论。精确正文和引用从已保存候选/绑定证据恢复，跨页主语、数字和限定条件仍需原文；不采用通用首尾截断裁掉科学资料中段。
- 每次尝试默认最多32次已结算请求、800,000累计token、32,000累计输出token（含摘要）；下一步前检查，达到后停止并保留保存点，不自动再开会话或重试。上限按已回报用量检查，正在执行的一次请求可能越过累计门槛；单次输出及父进程硬时限仍独立有效。显式重试的新增费用在生命周期报告累计，不能视为免费恢复。
- 模型调用前校验冻结MCP工具是否完整注册，缺失直接停止并记录工具启动分类；不让模型靠工作目录工具空跑诊断。
- 阅读复审仍先独立盲读完整准确稿；启用read_reader_review的冻结工具集只随任务书提供最近一轮完整报告，早期报告保留身份/开闭状态目录，确需时展开一个原报告。历史未声明该工具的任务不改变暴露方式。
- 运行记录保存策略参数、SDK版本、执行文件和适配器hash，上游commit未知就保持未知。压缩通过Harness的持久化替换API完成，不修改供应商隐藏推理协议。
- `GET /api/production/tasks/{id}/lifecycle-cost` 或 `scripts/inspect_production_lifecycle.py --task ID` 只读汇总该准确根任务及明确后继：全部尝试、摘要、失败费用、待审任务和故障指纹。不同重做根任务不猜配。人民币数值为现有定价版本的估算，缺失用量、未完成审核、搜索和人工成本明确保留边界；不是供应商账单。
- 验收比较作者返修加独立审核的可比阶段，分别列缓存、非缓存、输出、调用数及最终问题结论。不能用累计token下降替代费用下降，也不能以作者提交成功代替问题通过审核。

## 溯源与诊断窗口

只读工作集、研究条目及原文读取可返回很小的 `context_receipt`。宿主在业务调用返回后、MCP交付前持久化 `context_manifest`，记录公开字段/窗口身份、hash、尺寸、读取入口和完整性，不复制正文。规范读取标记表示宿主已处理资源，不证明模型收到或理解；不以日志替代产物和提交校验。

SDK适配器仅从实际 `tool/result` 的受控结果字段解析回执，核对本任务、本尝试、本会话、持久化回执及规范化业务 hash 后记录 `sdk_result_observed`。自由文本伪造、跨会话回执和变更载荷不关联。每次模型调用记录独立清单版本及仍在SDK可见消息中的已关联回执；消息替换后旧消息不计作继续携带。没有完整消息序号或头信息时标记不完整。

清单以 `(模型span, 内容hash)` 去重，不按 started 事件条数统计调用。每版使用独立事件身份，通用查看器可逐版展开。已关联 SDK 结果不等于供应商 HTTP 报文，也不等于模型理解或事实核实。模型隐藏推理不落盘。

| 只读入口 | 返回 |
|---|---|
| `/api/production/tasks/{id}/context-summary?attempt=N` | 契约、清单和关联数量、公开序列化尺寸，以及缺失清单、未关联回执、重复载荷诊断 |
| `/api/production/tasks/{id}/context-manifests?attempt=N&after=cursor` | 准确尝试的清单与送达事件，沿持久化序号分页；页内可能没有该尝试事件，仍按 `has_more` 继续 |
| `uv run python scripts/inspect_production_context.py --task ID --attempt N` | 同一只读报告，不领取租约、不启动模型 |

脚本加 `--compare-frozen` 可对历史制作任务计算新目录/游标的离线投影尺寸，并列出已采集旧整包返回尺寸。该结果不是新模型运行结果。聚合使用所有分页，不受旧 `.list()` 的前 1000 条限制。旧事件没有回执/清单时保持未知，不补造关联。清单最多256项，超过时显式标不完整；不据此自动省略材料。

## 当前边界

v1解决整包读取耦合、来源范围、研究写游标和可见上下文关联；v2增加可恢复候选、局部工具集及内容去重；window-v1进一步控制活动窗口和累计执行成本。显式重读仍允许。当前不基于模糊语义自动合并来源、不自动跳过独立全文审核，不承诺每个任务都因压缩省钱。跨模型策略及更广泛任务样本仍需分别验证。

没有改变模型输出上限或推理配置。离线回归及实际MCP进程能验证权限、版本、序列化和调用契约，不能证明真实模型生成质量或供应商输出触顶绝不会再发生。
