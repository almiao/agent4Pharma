# 四角色内容生产：操作与实现边界

## 节点上下文（ADR-118）

新采编根任务冻结节点工作集与按需读取工具，查询来源或研究条目不再取回完整稿件、底稿和评审。继续/重试沿原契约，历史任务不会仅因代码更新自动改成新工具。新契约研究写版本与继承版本分开；诊断查看不启动模型。生效范围、只读API与离线检查方式见[上下文运行契约](production-context-contract.md)。常驻服务需重载后才使用新排队代码；输出上限与模型配置未因此上调。

## 评审结论（ADR-103）

每个评审节点只有通过或要求返修：有必改即按问题单直接交作者，无必改才进入下一节点。阅读推进与文字自然度分别显示结论。沿用已有共用返修额度，耗尽仍未通过时显示“要求返修 · 自动修订已停止”，不进入新增人工改稿阶段，也不自动放行；最终人工定稿保留。工具或读取失败单列执行异常。

## 查看全部中间产出

制作列表展开“全部产出”，或进入制作详情查看同一轮次的完整目录。选题决定与任务书、背景调研各版、作者研究底稿各版、历版稿件、首次阅读观察、阅读评审、事实核验、图文包和改稿候选分别列出，可打开对应版本。目录包含失败/停止任务已经保存的产出；继承给后继或技术重试的同一底稿不重复列出。同论文的其他重做轮次分别查看。时间使用产物持久化的北京时间，原记录没有保存时间时显示未记录，不用任务更新时间补造。

## 阅读品质评审（2026-11-05）

新启动/重做的链在作者交稿后先进入“阅读评审”，查看吸引力与阅读推进、中文自然度两项报告及准确问题引文；随后独立事实核验。全流程自动作者返修默认5次、启动/重做可设到10次，阅读评审与事实核验共用；额度用尽仍未通过时显示“要求返修 · 自动修订已停止”。正文修改后旧稿阅读结论失效。两类通过均不替代最终人工定稿。旧冻结链不补跑，详见[阅读评审](reader-editing.md)。


## 当前采编流程（2026-11-04，ADR-092）

主编选题（摘要与必要背景）→作者研究与写作→编辑核验→图文制作→人工定稿。
不再先运行独立论文理解或背景阶段。作者在同一写作任务内先保存基于选题的研究底稿：
中心问题的回答、论文事实与出处、必要背景、未决问题及省略/限定/阻断处置。保存后继续写作，
不新排研究Agent、不等待人工确认；编辑与返工复用底稿。主编与作者可有界搜索背景。
继续/重试保留已保存底稿，仍从新的模型会话执行；未提交正文不能冒充保存点。
本条覆盖下文旧理解链与作者无搜索权限的历史说明；具体契约见[新闻技能](newsroom-skills.md)。


## 当前操作规则（2026-11-04，ADR-089）

关联推荐、启动制作、重做、继续/重试及接受改稿后核验等动作会直接调用模型并自动推进制作链，
不再需要单独勾选费用授权或选择执行几个阶段。任务串行运行，已提交产物保存后自动进入后继。
失败或资源准备超时会明确结束并显示原因；你仍可主动暂停、停止。最终人工定稿在独立节点完成。
本条覆盖下文历史说明中“只排队、不调用模型、再次授权、最多四个任务”等旧工作台操作语义。
旧未请求执行的队列可点击“开始制作”；新动作提交后不再需要逐段点击。

返修额度与评审结论见[阅读评审](reader-editing.md)；执行恢复见下文任务规则。

## 2026-11-04 论文精选完整重做（ADR-085）

已人工推荐的论文，在“论文精选 → 主文与操作”按当前推荐身份查找已有制作任务。有记录时显示“重做”，没有记录时显示“启动采编”。
确认启动或重做后，使用当前已发布的提示词和规范，从主编选题开始自动执行，并产生模型费用。
重做另建根任务，保留原稿、旧任务书与历史失败。确认框可查看既有重做记录。
“重做”不同于失败阶段的继续/重试；后者仍复用原冻结输入与配置。

日期：2026-10-30（Asia/Shanghai）。实现主编、内容、编辑和发行预览的内部生产闭环，复用既有情报正式候选，不改写旧批次。制作 schema v7、单篇回归观测 schema v8，首次打开应用存储时升级，升级前生成 `data/backups/discovery-pre-v7-*.sqlite3`。

## 任务模式（2026-11-03，ADR-071）

正式入口为七节点工作台的“稿件制作”。未立项论文也按原论文标题显示，进入后可查看论文理解、选题确认、写作和核验的真实父子任务；旧链还保留独立背景调查记录。成功提交的阶段标注“已保存”；已立项选题支持按原论文标题检索，并保留研究阶段过程。

- 暂停：暂停排队或运行阶段，撤销租约并中断绑定工作进程，阻止自动推进；已提交产物和已发生费用保留。
- 停止：结束当前阶段，保留停止记录；需要时可显式重试，不删除选题或历史。
- 继续／重试：复用上游保存点，以原冻结配置创建当前阶段后继，保留原尝试和失败记录。排队不调用模型，需再勾选费用授权执行。新的有界任务采用原每任务额度，原任务额度和用量不改写。
- 保存点是已提交的阶段产物；调用中途暂停后从本阶段重新执行，暂不提供模型会话中途无损续接。任务书已修订或选题已取消时，旧阶段不能直接恢复。

不再存在“同时只有一篇已立项”的名额限制；有限并发只决定后台排队，其他选题不会占住立项名额。既有历史容量阻断不会被自动重跑，需从准确失败任务显式重试。

## 本机管理台

```powershell
uv run pharma workbench --port 8765
```

打开 [中控主页](http://127.0.0.1:8765/)，按主编、内容、编辑、发行进入相应详情页。上游资料在情报筛选，来源维护网页已下线，单篇回归按离线操作说明执行；当前页面入口以[运行台说明](workflow-management-console.md)为准。旧工作台进程需要重启以加载新路由；旧 `/production` 入口已删除。

1. 选择正式推荐候选，点击“排队主编”。仅持久化输入快照，不发送模型请求。
2. 查看主编任务，确认本次模型调用授权及执行任务数，再点击“执行模型”。一次可执行一个阶段，或有界继续同一选题下游；不会启动其他选题。
3. 顶部选定选题，从同层导航进入主编、内容、编辑、发行分支，查看实际任务、状态、输入、配置版本和产物。节点目录来自装配角色，交接条件与返工边来自生产交接代码共同使用的定义。
4. 制作内由自动链读取绑定原文、按权限搜索及交接证据，不设人工粘贴补证或重新排内容任务流程。资料不足时如实保存 blocked；修复技术条件后可从准确任务重试，沿用冻结输入和配置，执行仍须费用授权。人工选题管理已删除（ADR-077）；独立编辑复议保留，不能使用旧租约提交过期结果。
5. 编辑通过后发行角色生成本地 HTML/Markdown 包；“导出当前有效渠道包”只记 `exported` 回执，不是外部发布。

模型缺凭证时页面明确不可执行，不用替身或规则结果伪装真实模型。正常查询/排队无需模型凭证。前端仍使用本机同源令牌与 Host/Origin 校验，不能直接对公网开放为多人管理台。

## CLI

```powershell
uv run pharma production list
uv run pharma production start --candidate <candidate_id>
uv run pharma production run <task_id> --allow-model
uv run pharma production continue <task_id> --allow-model --max-tasks 4
uv run pharma production resume <story_id> --role review
uv run pharma production export <package_id>
```

`run/continue` 会调用模型。`continue` 只推进本选题，达到任务数上限或遇到失败/阻断就停止；已排队下游保留。每任务默认最多两次尝试、180 秒硬时限、20 次补充检索/读取、每次模型响应最多 4096 输出 token。模型工具往返也会产生输入与输出用量，这不是整条链的费用或总 token 精确封顶；当前未实现按价格结算的父预算账本。仍需由操作者按本次额度授权执行。

2026-11-04（ADR-076）：已删除人工 `supply`、`resume-research` 与内容角色的选题级重排。`resume` 仅用于独立编辑复议；任务级继续/重试复用原冻结输入，不接受临时追加资料。历史资料及产物继续可读。

`export` 将准确包输出到标准输出；可由调用者自行保存文件。应用不接受模型提供任意写入路径。供模型使用的 `production-mcp/production-worker` 为内部命令，绑定持久化任务、角色和租约，不是通用操作入口。

## 角色与校验

| 角色 | 已实现行为 | 程序限制 |
|---|---|---|
| 主编 | 比较最多 20 个指定正式候选，在本任务主动补查决定性事实后提交报道或不报道 | 候选不能越界。报道时保存任务书并原子交接下一任务，不报道时记录当前理由并结束选题。 |
| 内容 | 读任务书、本地题录搜索、已有 URL 补读、提交稿件/引用 | 引用原文与关键表述必须实际存在；全文要求不能绕过；修订须逐项回应问题 |
| 编辑 | 独立任务和会话读准确稿件/证据，提交通过/必改/阻断 | 作者身份不可自审；必改不能 pass；事实阻断不自动放行，人工只能发起独立复议 |
| 发行预览 | 从编辑通过文本生成 local_html/local_markdown | 不允许实质改写、账号发送或伪造 published；包绑定选题修订、稿件、审核和 hash |

四角色提示词在 `agents/editorial/content/review/publishing`；每任务冻结提示词全文与 hash、模型、endpoint、输入和执行额度。更改配置不替换旧任务快照。独立角色会话不等同多模型交叉验证，当前仍使用配置中的同一供应商模型。

## 持久化与恢复

- 各业务使用专用仓储，制作工作单元协调同一 SQLite 连接；没有扩大 SqliteApplicationStorage。稿件与证据包以受限大小文本原子入库，首版不实现二进制媒体文件。
- 任务领取为短事务；网络/SDK 在事务外。结果、审核结论和下游队列同一事务提交，中断不会丢失已提交交接；此阶段用持久化任务队列承担交接，不另建外部 outbox。
- 执行任务具有有限尝试和租约令牌，过期可由 CLI `run` 重新领取；旧进程即使晚到也不能提交。后台进程重启不自动继续付费任务，需显式执行。
- 模型缺提交、SDK 异常、超时均记录未完成，SDK 异常只保存脱敏错误类型；业务校验以 MCP ToolError 返回安全字段级原因，输入/输出与错误进入管理台，不吞成成功。取消不会撤回已经发送的模型请求，但结果提交会被拒绝。
- 升级只增加表，历史材料/准则/候选不改写。恢复到 v6 备份后不支持新制作数据，不倒退迁移编号；本阶段没有外部发送，因此没有对外发布需要回滚。

## 当前实现边界

- 阅读评审、事实核验与人工定稿独立；执行异常与业务返修分别记录。真实模型质量不由离线测试证明。
- 作者在同一任务中研究、按需搜索并保存研究底稿与新闻骨架；不恢复独立论文理解阶段或人工粘贴补证。
- 图文批准、导出及公众号草稿箱交付见[图文制作](publishing-layout.md)，草稿箱交付不等于公开发布或群发。
- 旧单篇回归创建、续跑与执行入口已退役（ADR-083），历史观测只读保留。当前阶段重试复用冻结配置；完整重做另建根任务。
- 上游分主题查询召回尚未全面验证；缺失历史调用和用量不补造，未知不记为零或成功。

## 最新任务与停止制作（2026-11-04，ADR-087）

“论文精选”的采编状态与“查看制作过程”指向同一人工推荐下的最新制作轮次。
旧失败不会覆盖之后完成或新建重做的状态；打开旧任务可见历史标识及最新制作入口。
历史“制作容量已满”不代表现行限制：现在立项不受active选题数量限制，执行按队列与费用授权推进。
排队本身不授权模型调用。

在准确阶段点击“停止”并确认后，没有其他待处理分支的制作移到“已结束”，已保存产物保留。
失败/阻断阶段同样可以停止；停止不等同审核通过或稿件完成，也不改选题为取消。
如果还有并行排队、执行、阻断或暂停任务，该轮仍会显示在当前任务。
需要恢复已停止阶段时，可显式“重试此阶段”生成后继，回到当前任务；执行仍需授权。
新建重做属于独立轮次，保留在当前待立项，不因同一论文过去已立项而被归入历史。

此次重做任务submit_reporting故障已修复，旧阻断记录和原始提交参数仍保留。
隔离副本提交成功不等于生产已保存；正式产物只以实际成功提交的任务记录为准。

## 节点费用与参数失败恢复（2026-11-05）

制作阶段按钮显示各节点人民币估算，任务详情的“计价依据”列明当前价版本及统计边界。费用包含该任务失败尝试，按用量累计增量计费；无回报显示未知，记录不完整显示部分。按回报时间判断北京时间高峰/空闲并处理2026假期；历史重估不是账单，不含未知搜索/抓取费用，准确规则见ADR-108。

非法JSON会在原会话/硬时限内最多纠正一次，再失败明确显示MALFORMED_RESPONSE。不会执行模型生成的.replace等表达式，也不会自动把研究类别改成稿件类别。上下文明确返回本任务版本和必读资源；当前历史失败仅增加只读诊断，不自动重试或补跑。

模型会话以 `max-tokens` 结束时，明确显示单次输出达到上限，不再归为笼统的 RuntimeError。
诊断只采用准确任务、准确尝试的公开结束状态，不读取隐藏推理或凭正文猜测。
供应商明确返回 `SERVER` 与状态码 `500` 时显示模型服务内部错误；不展示原始供应商诊断，也不据此增加自动重试。
明确返回 `STREAM_CLOSED` 时显示响应流中断；不同失败类型以最后一次准确模型调用为准，不用较早的错误覆盖后续结果。
重试仍须显式请求，并复用冻结的模型、输出上限和已提交保存点；未提交输出不作为新稿保存。

## 自动返修候选与恢复

新协议任务在同一作者阶段小步保存候选，工具过程中的saved只表示候选已落盘。预检失败会保留候选并返回问题；只有正式提交后才生成新稿、进入独立阅读和事实核验。候选不表示稿件已通过。

暂停、失败后的继续/重试继承准确候选版本与冻结原稿，作者可查看diff及history恢复明确保存点。重做另建新根任务，不继承候选。历史v1任务继续使用原补丁提交契约；部署新代码不会把旧任务升级。详情仍使用通用工具过程查看保存版本、预检反馈与提交结果，未新增候选专用编辑页面。


新根任务的revision-window-v1会卸下旧候选上下文，并在有必要时有界压缩历史。摘要不是保存点，准确候选与来源仍可按需重读。达到累计执行预算时停止保留候选，显式继续前应查看进展和费用；不会自动反复开新会话。`/api/production/tasks/{id}/lifecycle-cost`与`scripts/inspect_production_lifecycle.py --task ID`汇总该根任务及后继全部尝试、费用估算和待审边界；只读查询不触发模型。
