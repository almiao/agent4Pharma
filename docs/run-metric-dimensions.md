# 运行卡片的统计维度盘点

2026-10-31。卡片只展示一个主维度；“查看全部”按维度分组。每组固定统计对象、单位和范围，不把总量、状态、处理方式和历史子集平铺成同级结果。

| 卡片 | 卡片主维度 | 详情中的独立维度 |
|---|---|---|
| 来源与采集 | 来源采集状态：待采集、采集中、完成、部分完成、失败、其他 | 来源记录规模、去重资料规模、重复/复用标记、完成来源的空结果 |
| 粗筛与分流 | 参与粗筛来源项的结果：待处理、筛选通过、未通过、筛选失败 | 全批来源项的处理方式：直送、复用、已有粗筛判断、粗筛尚未完成 |
| 情报精筛 | 来源项的最终处理结果：待处理、处理中、处理失败、正式推荐、未通过 | 全文取得、摘要取得、历史评估分别列组；不再单列观察、待人工补证或处理完成 |
| 主编选题 | 候选的处理情况：待处理、已有编辑决定 | 当前任务处理状态、编辑决定（份）、选题状态、历史任务 |
| 内容写作 | 当前写作任务的处理状态 | 稿件当前/历史版本、任务返工属性、稿件交审情况、历史任务 |
| 编辑核验 | 当前核验任务的处理状态 | 当前稿件版本的审核结论：通过、要求修改、业务阻断；历史审核版本、历史任务 |
| 发行归档 | 当前打包任务的处理状态 | 包有效性、包是否导出、导出回执条数、历史任务 |

## 互斥与求和

- 粗筛先排除直送和复用，再按“错误 → 通过 → 未通过 → 待处理”唯一归类。直送没有粗筛结论，不能算作筛选通过。历史补证和未知分流归待处理，不靠未知状态推断通过。
- 粗筛的处理方式组覆盖全批来源项；已有判断不包含直送/复用。它与粗筛结果组的统计范围不同，必须分别列出总量。
- 精筛按准确来源版本绑定的最新有效任务归入五个互斥结果。未建/排队归待处理；运行归处理中；技术失败、中断、阻断以及完成但缺少有效结论归处理失败；成功评估后 recommend 归正式推荐，其余有效结论归未通过。历史 watch/needs_evidence 只保留为未通过的原因，不再生成人工观察或补证待办；全局待处理入口也不再将这些已完成结果列为待补证。旧冻结评估及模型策略不被展示归类改写。
- 所有注明总量的分区，每个对象只在一类出现，分类数量之和等于该组总量。来源筛选后，详情总量随同组明细一起重算。接口失败的组保持未知，不输出伪零。
- 任务、候选、资料、版本、包和回执是不同对象，不跨组相加。重复/复用、交审、返工等子集标记明确注明可以与状态交叉；不能把子集再加到总量。
- 未替代旧统计或改写数据库状态。旧指标仍支持原深链接，默认卡片与详情仅使用具名维度，避免把内部诊断指标再次平铺给用户。

## 验证

前端回归覆盖错误优先级、直送/复用与通过分离、每组数量守恒、对象无重复、未知保持未知，以及详情指标对应的准确来源版本。
