# 运行节点数据口径

日期：2026-10-31（Asia/Shanghai）。本说明对应实际运行工作台，不是原型数据。

## 公共约束

- 批次模式读取完整批次成员及其明确父运行的情报任务；没有全库最近 100 次截断。选题模式只使用明确候选与任务引用，未关联采集显示未知。
- 来源项按 source_record_id，去重资料按 material_id，任务按 task_id，稿件按不可变版本分别计数。同一缓存判别可关联多个来源项，不能用判别缓存数代替处理文章数。
- 每个指标与抽查集合共用同一对象列表；展开工序保留 ids 快照（包括合法空集合）。身份引用、来源和状态可以进一步筛选，正文按对象读取。
- 无记录、查询失败、未执行、业务排除、技术失败分别表达。只读查询不执行网络、模型、重试或发行，不写回历史批次。

## 来源与采集

默认展示逐来源表：来源名称、归档来源项、去重资料、采集状态、进入精筛、不进入、待粗筛、粗筛失败。记录数、去重数及四种分流数均可点击抽查；来源名称进入本来源文章列表。

来源任务状态来自实际 jobs：未启动（冻结计划有来源但尚无来源任务）、pending、running、complete、partial、failed。成功空结果为 complete 且归档量为 0；没有成功进度的失败量保持未知。已归档资料即使游标因失败重置也保留可见。

来源清单取本批冻结 sources 与实际来源任务并集，不用现行计划改写历史覆盖。显示名称可引用当前目录标签，不参与运行身份。来源不在本批计划内不计失败。

**归档量不是原始 HTTP 返回条目总数。** 现有账本未逐条保存清洗前被丢弃的所有记录或每次重复返回，因此不提供虚构的“抓取总量/丢弃量”。窗口和安全错误、尝试数可在来源预览中核对。

采集与粗筛明细支持期刊、预印本、新闻、公告、其他、未分类按钮，并可叠加具体数据源；数据源按名称排序且支持多选，抽查列表另可按入选/未入选筛选。分类来自明确来源身份、类型或归档元数据；无法确认时不猜测。当前来源目录只补充展示类别，不修改历史成员及状态。筛选条件随链接保留到来源项列表，指标与抽查列表同步过滤。流图卡片仅显示名称、状态与数量，移除序号及常驻解释文案。

## 粗筛

- 输入为完整批次来源项，analyze/exclude 按来源项关联统计，不按 DISTINCT 判别缓存计数。
- 待粗筛为 awaiting_triage 且没有当前错误；技术失败从 rss_triage_errors 读取，失败仍留在待判断业务状态，但只进技术失败集合，不重复算普通待处理。
- 历史第三路、既有评估复用和未分流/其他状态单列，不将它们归入新版排除。
- 同来源页可筛标题、处理状态并核对准确来源版本、粗筛输入/策略/模型引用与失败原因。
- 来源项详情以原文为先：标题后直接给出来源、类别与状态，能取得原文地址时显示“打开原文”和完整 URL，其后才显示已保存正文、摘要或访问受限说明；未保存原文地址时明确提示，不展示无法打开的链接。内部标识、路由与任务引用收进默认折叠的技术追溯区。
- 现有粗筛没有逐来源项的持久化运行租约，不能推断某一篇正在推理；当前未形成判断的对象保持待处理或失败，不伪造逐篇运行中数量。

## 情报精筛

- 按 parent_ref 精确读取本批全部评估，并用批次资料身份核对。正式/回放/自检分开，当前状态只取同一来源版本和模式中最近更新的任务，已替代评估独立留作历史。
- 展示正式候选、推荐、观察、范围外、待补证、待执行/运行中、失败/中断；另外识别 analyze 后尚未创建精筛任务的来源项。
- 摘要状态来自实际 abstract_status，全文由 source_fulltext/primary_fulltext 且 available 确认。primary_page 只算范围未确认，URL、推荐结论或 PDF 文件存在不能冒充全文。
- 证据读取失败与业务排除独立，摘要已取得不等于原文已取得。

## 主编选题

- 选题按 active/deferred/cancelled/completed 查看。候选可尚无决定，新主编任务只提交 commission 或 decline；历史 defer、request_evidence 仍显示原决定。
- 编辑决定来自已提交的 editorial_decisions，保留原因、重看条件及候选引用，不从模型自由文本猜测。
- 任务上下文投影 candidate_ids 和 assessment_ids，尚未立项的主编任务以及候选池后来更新的历史选题仍可沿原评估引用定位。排队与实际模型执行分开。
- 合题允许多个候选关联一个选题，候选数与选题数不相减作为积压。容量限制仍由原立项用例检查，不从一般失败字符串自动推断“容量阻断”。

## 内容写作

- 当前稿件为每个选题最新 number、匹配当前 brief_version 的稿件；旧稿、已取消选题稿件不进入当前产出。
- 失败/阻断/排队/运行中按当前 active 选题 revision 校验任务，过期失败独立展示，不作为当前报警。
- 返工由内容任务输入中的真实审核引用识别。已交审从实际审核任务对 draft_id 的引用确认，不需要等审核完成才算交审。

## 编辑核验

- 默认只看当前稿件最新报告，同时核对 draft_hash 和 brief_version；旧版本、旧报告和已替代复议报告分别保留历史。
- 当前通过、要求修改、阻断与任务执行失败分开。新版稿件保存后，旧版的“通过”或“要求修改”都不再冒充新稿件结论。
- 新版待审由准确审核任务的 queued/running 状态体现，问题正文仍在对应审核产物内阅读。

## 发行归档

- 当前有效包、失效包、已导出的包和本地导出回执分别统计。
- 查询与实际 export_package 使用同一个 require_current_package：检查 completed 选题、任务书版本、选题修订、最新稿件以及包内容 hash。只读有效性检查不产生回执。
- 导出时再次校验，不信任页面快照。历史回执保持真实，不因包日后失效被删除；现有本地导出回执按包幂等，不能把反复点击计为多次独立发行。
- 外部发送未接入，不展示虚构的发布成功数。

## 契约与验证

`GET /api/discovery-run?batch=…` 返回具名 DiscoveryRunSnapshot；批次目录最新 50 项，明确指定旧批次仍可读取，其成员不截断。来源任务通过 JobRepository 读取，资料快照通过 MaterialRepository 读取。

`GET /api/intelligence-tasks?batch=…`、`GET /api/candidates?batch=…` 按明确父运行读取，不混入其他批次。选题冻结输入通过 `task_ids` 读取明确评估（单次最多 200 项），不会退回全库最近记录。`/api/production/artifact-summaries` 增加 current、validity、task_links、decisions、receipts，不输出正文或隐藏输入；原有 status 字段保留兼容。

离线回归覆盖缓存复用与来源项数差异、失败不变排除、成功空来源/未启动/部分失败、精筛父范围/当前性/证据状态、任务书变更使旧包失效、新稿件使旧审核失效、只读查询不记导出回执、HTTP 令牌保护。真实库浏览与隔离库写用例分别验证，不以离线提交充当真实模型质量验证。

## 本地归档汇批（2026-10-31）

`uv run python scripts/consolidate_archived_records.py --root data --batch <新批次ID> --archive <归档目录>`
可重复传入 archive；不指定时仅汇主库。操作先保存 SQLite 一致备份，显式来源修订经 SourceEdit 校验并写审计。
新批次包括主库 demo 及所列归档资料，按来源/外部 ID 选择最新来源版本，跨来源保留独立出处，资料仍按原身份去重。
归档元数据及原始证据按原身份导入，文件校验 SHA-256；缺失/损坏导致本次导入数据库回滚。旧批次、模型评估、游标和归档库不改写。
来源“完成”仅表示本地归档导入完成，不表示今天重新采集或历史来源覆盖完整。请求记录归档路径和选择规则。
汇批冻结当前已发布筛选/精筛准则，把新资料统一交本地预选；启用 Decider 时全部待判，未启用时直送情报队列，关键词不参与去留。
不调用采集或模型；相同批次 ID 重跑不追加资料，后续新输入另建批次。已发布标准的历史状态不由此命令迁移。
通用网站、会议、出版平台和标识符服务归“其他”；新闻栏目归“新闻”；公告平台和监管披露归“公告”。未知新类型仍保留未分类。
旧 demo 来源项在读取时适配为公开资料快照，不回写原始元数据。

## 历史清理

2026-11-07 已移除一次性空来源补采及其收尾脚本。新采集使用正式工作台的日常执行入口；旧补采批次、失败事实及并回记录保留。

`uv run python scripts/prune_discovery_history.py --root data --keep-batch <活动批次> --keep-batch <补采批次>`
先备份、清理无引用历史，再输出 data/reports/history-cleanup-20261031.json 的无引用文件清单。
可用 --active-batch 与 --retry-batch 同时将补采并回汇总批次；原评估 parent_ref 不改，摘要/候选按明确来源项引用纳入。
有评估、制作或回归引用的旧批次会自动保留；source_records 的旧版本和 artifacts 只有在无业务引用且无 raw_refs 依赖时删除。
当前来源版本可复用的本地预选缓存保留，策略版本、来源、选题、稿件、审核不在清理范围。
数据库清理只返回文件清单；执行文件删除前再次核对数据库现存 storage_uri 和数据目录绝对边界。

## 文章阅读详情（2026-10-31）

来源项列表返回公开原文 URL；正文不混入整批列表。点击文章或恢复 record 深链接时，使用
`GET /api/discovery-run/article?batch=…&record=…&offset=0` 读取该批实际来源版本。
接口先校验来源版本属于本批次，再通过资料仓储读取归档正文，每页最多 20000 字，next_offset 可续读。
正文、部分片段、仅摘要、仅链接、访问受限及归档文件缺失分别表达；不将摘要/片段称为已保存全文。
页面以标题、来源、打开原文按钮、完整 URL、可读正文/摘要为主；技术追溯信息默认折叠。
正文以纯文本呈现，不执行来源 HTML；外链只支持 HTTP(S)，新标签页启用 noopener/noreferrer。
打开详情不联网抓取或调用模型，不更改历史元数据、正文、评估和处理状态。
当前来源目录的明确身份优先于陈旧采集计划的默认媒体类别，修正 BMJ 等期刊的展示类别。

## 采集失败详情与重复标记（2026-10-31）

- 采集节点的失败数量、来源列表名称及来源表状态可打开采集任务详情；即使本来源没有文章，也能阅读错误、实际尝试次数、窗口和请求地址。来源文章页的 collection 参数可直接恢复同一详情。
- 请求地址优先来自任务/冻结计划，回退当前目录时明确标记“非原任务留存地址”；补充复核保留自己的 URL、记录时间、HTTP 状态及原因，与原始错误分开。
- 旧失败来源的实际复核报告可经 CollectionDiagnosticsRepository 按批次/来源校验后追加留档，不覆盖原错误、游标和状态。只有诊断、没有采集 total 时，取得量仍未知，后续失败也不能因此变成部分成功。
- 新 RSS HTTP 错误保留响应状态码，不保存响应正文。
- 重复来源项按本批明确 material_id 标记，可跳到该资料的另一来源。明确 already_seen 才标“已复用，可忽略”；新版本和已归档但待重评的资料不建议直接忽略。
- 重复来源项和可忽略复用分别计数、筛选；这些是只读提示，不改写历史成员、判断状态或自动删除资料。同一资料的不同来源仍保留证据出处。

## 来源当前采集能力（2026-10-31）

来源目录和采集任务详情展示同一 `collection_availability`：采集入口已验证、当前无法采集、待接入。显示原因与复核时间，可展开逐次检查的地址、HTTP/解析结果；旧任务状态与当前来源标签分别显示。无复核证据的来源不自动获得可用标签。

`scripts/recheck_failed_sources.py --batch <失败批次> --alternatives <官方替代链接 JSON>` 显式联网检查公开入口，不调用模型、不更改任务；输出有界响应证据和 assessment.json。入口逐次经公开地址校验和正式 Feed 解析，并核对频道身份；不能将 HTML 验证页或姐妹刊当作成功。

实际补采另建新批次并回汇总批次；原批次的失败事实不改写。当前 Feed 的有界快照不代表历史窗口全覆盖；恢复后的题录仍走后续筛选流程，不能把入口验证当作原文或精筛成功。

## 流转数字与批次范围（2026-10-31）

卡片及详情的最终分组以[统计维度盘点](run-metric-dimensions.md)为准。主卡片只读一个结果维度；详情按统计对象和维度分组，不再平铺所有内部指标。

- 默认读取最新的未并入其他汇总批次的运行；已合入的补采不会取代汇总成为默认。显式 batch 链接仍保留原范围，补采视图提供返回汇总入口。
- 方框内优先列本环节主要及非零结果，最多四行；正式推荐等主要结果优先保留。零结果和超出行数的分支收进“··· 查看全部”，每行及全部详情均可点击；全为零显示“暂无处理结果”，未知数量保留为 —。不再放统一主数字。本地判别通过与直送精筛分别统计；直接分流不伪称粗筛模型已运行。
- 精筛框统一列待处理、处理中、处理失败、正式推荐、未通过；历史观察和待补证仅作为未通过原因留在详情，不生成待人工补证分支。待创建及执行状态沿准确来源版本关联，不能因同资料的另一个版本已有评估，就把本版本从待办减掉。查询失败的任务状态保持未知。
- 连线数字统一表示下一个环节的输入总数，点击仍可抽查该集合；各环节保留自己的单位，不强制将来源项、任务、评估和稿件拼成一个递减漏斗。发行输入使用当前审核通过的版本；写作输入仅统计当前写作任务，不把历史失败重试重复计入。
- 汇总批次认可成员中冻结的 intelligence_task 身份；原评估 parent_ref 不变，前端不得再仅按汇总父批次过滤掉这些已导入评估。其他批次的同资料评估不自动算入。
