# 工作台交互性能

更新：2026-11-05。

## 200 ms 目标与测量

普通按钮点击、筛选、集合切换、输入/产出切换，应在 200 ms 内呈现可见响应。
本地只读查询同时以 200 ms 为优化目标；浏览器的事件耗时、点击后的首帧、接口完成和内容就绪分别记录，
不能以加载提示出现代替查询完成。冷启动、依赖服务探测、PDF、采集与模型任务需单独记录完整耗时；
执行动作立即显示处理中，后台完成前不得报告成功。

本轮基线发现：制作清单逐任务扫描完整 trace、所有制作查询申请 SQLite 写锁、全局活动解码全部历史筛选运行，
以及情报页重复读取约 17 MB 的预选历史。原采集批次包含 6081 个来源项，不能用新建空批次作为优化后对照。

## 实现与边界

- 制作快照使用显式 `read_only` 工作单元，以同一事务读一致快照，`query_only` 禁止写入。
  领取租约、阶段控制和提交产物仍使用原写事务。
- 制作列表通过 `/api/production?view=summary` 省去执行日志；准确详情仍显示实际用量。制作阶段展示装配时的角色模型，读取列表无需加载排队时使用的发布提示词或新闻技能。
  用量读取在持久化层按 `token_usage` / `model_execution` 筛选，普通 trace 继续按游标查询。
- `/api/rss-triage?view=triage|rank|ingest` 只读取对应集合。排序读取一个准确运行及轻量目录，
  历史运行切换按原 ID 查询；不截断排序池，也不改写冻结配置。原完整历史查询保留。
- 全局活动先选每批最新运行，再解码；只计算进度，不生成整池论文卡片。
  来源版本通过资料仓储批量读取，缺失仍报错。机构匹配复用已编译的别名，并保留原词边界。
- 大批次采集投影最多缓存八个范围，由独立只读连接的 SQLite `data_version` 监测真实提交；
  提交或数据库文件替换立即失效，计算期间发生提交不写缓存，返回独立对象。服务关闭释放连接。
  此为服务端投影复用，浏览器 API 仍 `no-store`，不使用 TTL 延迟新状态。
- 浏览器仅合并同时发生的相同 GET，完成后不缓存接口结果；POST 前后隔离在途请求。
  工作区最多保存八个范围的已读快照，切回时先呈现并重验，修改时清空；后端继续复核准确版本及权限。
- 任务输入/产出切换复用已读记录；执行记录独立按需读取，分页串行推进。
  调用树建立使用索引，原始大 JSON 在展开时才序列化。
- 服务健康和 PDF 解析任务分别在对应抽屉页签打开时查询；全局任务仍独立轮询。
  这些读取不启动依赖服务或业务任务。
- 通用动效缩短为60–120 ms；系统要求减少动态效果时关闭通用动效，避免抽屉关闭继续阻挡下一次点击。
- 来源、提示词及样例代码分块加载。带内容哈希的 JS/CSS 可长期缓存；HTML、API、错误及固定文件名资源仍 `no-store`。
  支持协商 gzip，保持 CSP、同源和令牌校验。

## 验证记录

本轮在隔离只读服务中使用 SQLite 备份及筛选运行修订副本验证，所有 POST 明确拒绝。
截图、浏览器事件与接口时间、检查日志见本地 `data/reports/ui-performance-20261105/`。
结果区分实际浏览器检查、离线契约验证和未执行的付费动作；不将局部抽样写成每个按钮均已实测达标。
运行中的 Python 服务需要重载才使用后端优化；前端构建产物不能证明服务已重载。

最终验证：普通动效下63次只读交互39–110 ms，样本P95 99 ms；526项Python测试、97项前端测试通过，
Ruff/格式通过，架构0错误/44提示，构建完成。串行热态样本：制作列表41–50 ms、精选103–122 ms、
6081条采集清单缓存命中55–56 ms、初筛80–98 ms、排序141–175 ms、全局活动122–141 ms。
精选/采集第一读分别测到544/296 ms，并发请求仍有200–370 ms，依赖探测约690 ms，不能宣称所有接口均小于200 ms。
隔离副本缺少MinerU运行资料，解析任务查询真实返回400；未触发付费操作，未重载原8894进程。
详细样本、错误与复现脚本见上述本地review.md。
