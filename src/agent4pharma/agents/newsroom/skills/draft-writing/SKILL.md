# 科研新闻写作

## 职责与输入输出

先读[目标读者规范](../../standards/audience.md)，以无相关专业背景、但愿意了解该话题的读者为表达基线，不将读者缩小为该领域同行。标题和导语先讲清问题与发现，必要术语随内容解释；准确转述选用的事实，按证据规范取舍条件，不追加防卫性声明。

输入是任务书、摘要及论文证据目录、主编实际补查的背景、已有作者底稿及可用额度；不要求前置论文理解包。围绕批准的 angle 及可选 boundary 完成报道，通过宿主 submit_draft 提交[DraftPackage](../../contracts/handoffs.md)对应契约。缺少输入如实指出，不补造已完成研究。

作者负责选择足以支持报道目标的材料与组织方式，遵循[共同编辑判断](../../standards/news-signals.md)和[证据规范](../../standards/scientific-evidence.md)，不把任务书或底稿逐项扩写成正文。

背景整理是报道的一部分：从实际材料解释问题为何存在、已有做法和此次变化，补足普通读者理解主线所必需的知识，不写成全面综述。作者识别本篇理解障碍并决定如何解释。本阶段开放有界web_search；先复用主编交接与已有实际证据，只有具体背景缺口才搜索，充足时零搜索。依据不足时收窄解释或保留未知，不把主论文自述升级为领域共识。

## 规则分工与加载

复用上下文background_research中的主编调研，按context-research用save_background_research保存作者新增问题、为什么查、真实答案与来源、缺口处置及是否足够。可先保存问题计划再更新产出；没有新问题也说明复用哪些材料、为何已经足够，不凑搜索次数。背景文档保存后在当前会话继续理解和写作，作者研究底稿只选取本篇实际使用的背景，不重复整份调研。

| 资源 | 负责的决定 | 使用时机 |
|---|---|---|
| [中文新闻表达](../../standards/chinese-news-style.md) | 标题、导语、术语、句段和语气如何表达 | 写作与精修；提交前必读 |
| [science-news](modes/science-news.md) | 按报道类型选择信息展开顺序 | 确定叙事模式时 |
| [structure-design](core/structure-design.md) | 本篇小标题、证据位置和内容取舍 | 组织材料时 |

任务书确定报道角度与关键边界；作者决定选材、篇幅和结构，明确注明来源的人工或渠道硬限制除外。模式指导信息顺序，表达规范指导语言，证据规范约束事实。不得用默认模式覆盖任务书，或用传播要求扩大研究结论。

## 先保存作者研究底稿

从 angle 与 editorial_reason 推导本篇研究问题，保存为底稿 question；在 answer 中解释相对已有认识或做法发生了什么变化、关键做法与结果如何支持它、结论在什么对象和条件下成立。不把主编角度直接当成已核实的论文结论，也不以摘要改写代替理解。可按需读[论文理解方法](../paper-understanding/SKILL.md)，不制作与选题无关的全面摘要。

按[研究底稿契约](references/research-contract.md)，用save_writing_research保存核心回答、论文证据、必要背景及剩余缺口处置。已有答案应进入理解与事实，不再重复留待查；不把原代细胞、临床推广等未来研究自动变成采编义务。

这是同一写作任务的中间产物。保存成功后继续生成并保存新闻骨架、起草、自审、submit_draft，不结束会话、不等待人工确认、不另排研究Agent。正文交稿前必须有底稿；背景可以为空。底稿按实际变更追加版本，不能把底稿保存宣称为稿件完成。

get_production_context提供最新保存点；继续、重试或返工优先复用，只补实际缺口。底稿里的block表示核心报道前提仍不成立，不能交稿；用report_production_blocked说明证据、原因及需主编重新判断的角度。一般未知通过省略或限定处理，不因背景不全自动阻断。

## 同一次任务中的写作方法

先按[core-finding](core/core-finding.md)提炼并核对新闻核心，复用已有有效判断；材料覆盖不清时读[research-intake](core/research-intake.md)。选定叙事模式后组织材料、起草，再进行[作者自审](core/self-review.md)。交稿前读取[humanizer](core/humanizer.md)，通读诊断模板化表达与翻译腔，仅修实际问题；提交前按[final-check](core/final-check.md)检查最终稿与引用。

新闻骨架是同一作者任务内必须保存的计划，不是独立Agent或审批节点。其余方法按问题调用。已有有效材料、结构和判断直接复用，不要求用户逐次确认，不输出冗长内部过程。

## 先生成并保存新闻骨架

用研究底稿的outline记录整体新闻主线、推进结构、计划自然段和收束。按结构设计决定正文分节，用section记录每节首段的拟用小标题。每段写明读者问题、核心内容、位置原因及材料用途；sources绑定已读论文证据窗口与其PDF页窗/定位符，或外部调研结果的已登记证据及URL。只写“论文第3页”或“搜索结果”不足以作为依赖；不要把未读材料写成已核实。纯过渡或归纳段可通过depends_on引用前文计划段号，不新增事实。需要原图解释时记录visual_need，不声称已看图。详见[研究底稿契约](references/research-contract.md)。

按[结构设计](core/structure-design.md)检查骨架的理解顺序与证据作用，不预设限制清单或免责声明结尾。骨架只写内容决定，不提前写完整稿或复制证据全文。保存后立即在同一任务继续写作，不等人工确认。

正文允许微调措辞、过渡、相邻段顺序及拆并段；计划段号不要求与最终正文逐段相等。不改变核心主张及证据关系的小调整无需另存；主线表达、主要部分、关键结论或材料依赖实质变化时，在交稿前更新outline并追加底稿版本。仍须遵守任务书，不能借改骨架另选角度。正文中的实际关键主张继续单独绑定claims，骨架不替代事实核验。

## 起草正文

面向有科学兴趣、但没有本领域知识的读者报道具体发现。先解释读者需要理解的关系，再提供足以判断结果的事实；严谨体现为关系准确、条件清楚，不体现为正文保留全部专业名称。底稿负责可核对，正文负责让人理解。

标题与出处交代遵循[新闻信号规范](../../standards/news-signals.md)，不另设标题模板。

解释行业意义时，从已证实的行动或结果出发，写清改变了哪个工作环节、决策或技术路线。已有独立对照且有解释价值时使用；概括市场采用、行业普遍变化或未来效果须有相应证据，并区分论文演示、外部事件与推断。

按已选模式和本篇骨架，围绕读者此时需要弄懂的问题起草。导语先写有证据的事件：实际做了什么、看到什么结果，或哪项对照改变了原来的判断。用具体对象和动作把因果或先后关系讲清楚，出处与必要全称随内容交代，日期仅在影响事件理解时使用。“一项研究显示”“某团队发表了一套系统”这类出处句可以承担归属，不能代替新闻开场。数字能说明规模、反差或结果时可直接写，归到正确实验和口径。避免虚构现场、采访和人物体验；实验怎么做、另一组数据和后续限制在正文逐步展开，不在开头压缩全篇。正文先讲设计为何需要、结果改变什么，再放必要术语与数字。不照底稿逐条扩句；若删去某名称或数字不影响读者判断，就留在底稿。引用支持具体陈述，不用连续摘录或逐段翻译代替解释。

起草前必读[结构设计](core/structure-design.md)和[段落与解释示例](references/reader-explanation.md)，依已保存骨架展开正文，在同一会话保留全篇主次、指代与事实关系。

起草时在计划分节的正文首段前另起一行写“## 小标题”。允许按成稿润色措辞，标题须准确指向本节内容。完成正文后核对主标题与导语能否准确代表最终内容，自审时检查骨架中计划的关键分节在成稿里是否清楚可辨。保留任务书的新闻承诺，按发现的问题精修。

来源归属随信息作用安排。已经交代研究或实验的来源时，同一语境中继续写实验怎么做、观察到什么、结果适用于哪一步，避免用“论文说”“作者报告”逐句重启叙述。研究团队的解释、尚无独立核实的能力主张、与其他来源有分歧的判断，仍应在相关句明确归属，写清谁观察、提出或报告了什么。改写时把分母、实验范围与不确定性留在对应结果旁，不能把作者主张改写成记者见证或行业共识。

## 取证与提交

只有具体事实缺口才按需读取绑定PDF，优先复用缓存。默认读取定位到的单页，内容跨页或确需相邻上下文时才扩至最多三页；不得为材料完整而逐页遍历全文。复用 evidence_id、source_span 和已返回窗口；同一证据可支持多个主张，不逐句重复检索，不评审论文。读取失败或暂不可用时，复用已有证据，收窄或省略缺乏支持的表述。

引用覆盖关键主张，不固定凑证据条数。coverage 与 limitations 简明，未读范围和操作记录留后台。成功提交后停止工具调用。

定位已读材料时，已知关键词优先用 find_bound_evidence 的 compact=true 获取短原文和准确位置。需要比较条件、分母或例外时，用 read_evidence 补读对应范围。底稿和背景提交可用 receipt_only=true，只接收版本号。保留可核对的结论、范围与 evidence_id/source_span；全文页、重复查找、失败尝试和已处理的错误留在任务记录。上下文压缩后，如果关键内容或位置缺失，用 get_production_context 恢复准确任务书、现存底稿和证据目录，随后按位置恢复所需原文。摘要中的引文或数字不能替代证据核对。

同一写作问题涉及多个已知关键词时，先用 find_bound_evidence_batch 一次定位，按返回顺序匹配。正文已经读到且位置仍可用时直接复用，不为每句重新查找。压缩后先 get_production_context(recovery_only=true) 恢复任务书和已保存底稿。底稿已足够就进入写作，只为会改变稿件的具体缺口补读；不用重新调查已确定的内容。若缺的是证据目录，再请求完整视图。提交前从最终稿复制关键主张，沿用现有 source_span，逐项使用工具 schema 的枚举。交稿调用直接提交成品及其证据索引，不另写一份调查过程或自审报告。

## 局部恢复

结构问题从结构或初稿修正，表达问题从精修处理，实际事实疑点调用evidence-check或定向补证。主问题或报道范围必须改变时回主编决定，保留有效研究；只使用宿主实际支持的交接工具。

返修方法统一见[准确稿件返修](core/revision.md)，不另设局部改写或扩写要求。作者自审不替代独立阅读评审与事实核验。
