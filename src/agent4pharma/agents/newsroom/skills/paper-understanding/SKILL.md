# 论文理解

围绕已批准的报道问题理解原研究，不把摘要逐句翻译成长段，不另交立项前理解包。遵守[证据规范](../../standards/scientific-evidence.md)，先读[目标读者规范](../../standards/audience.md)。解释理解核心问题必需的陌生概念，完整保留数据、条件和限制；不因面向跨专业读者而提前删掉专业事实。
作者底稿使用[研究契约](../draft-writing/references/research-contract.md)，按主要贡献读[类型方法与对照示例](references/paper-types.md)中的相关部分。

## 理解方法

1. 确认研究对象与实际任务。区分技术手段、研究结果和最终用途；细胞表示学习不等于细胞模拟，动物结果不等于临床获益。
2. 辨识相关贡献类型，不要求输出分类字段。组织“具体困难 → 关键做法 → 如何应对困难”的解释，先用通俗语言讲作用，再给必要术语；不堆模型名和实验目录。材料未解释内部机制时，不凭方法名称猜实现或兼容范围。
3. 提取对报道中心问题最重要的结果，保留对象、比较条件、指标方向和原文已有数字。数字未知就留空，不写占位数字。
4. 意义段用1–2句解释已报告结果对相关研究或工作的直接用途，区分作者观察、作者解释和自己的推断。每段解释关联已定位的发现；所有事实前提必须在这些发现的来源中。条件语气不能为新增能力、免去某步骤、扩大适用范围提供依据。
5. 对照已读材料消解问题。已有答案直接进入理解与事实；仅保留影响报道的真实缺口，并选择省略、限定或核心阻断，不机械制造科研评审问题。

## 材料与停止

摘要足以解释主线即可交付。只有方法逻辑、核心结果或条件存在具体缺口时，使用 read_document 定向读取绑定PDF缓存的1–3页；不遍历全文，不要求完成科学评审。缓存未就绪则继续可支持部分并留下具体问题。
论文内容以作者报告的事实准确归属。原文未读取不等于研究未报告。作者按需要使用已开放的背景搜索，不为全面性展开调查。
来源身份、已读范围和工具状态统一留在 research_scope，不塞进一句话结论或反复写进解释。limitation只保留影响此发现含义的具体适用条件；没有独立验证、未读全文等工作记录不当作科研缺陷。意义段正面解释对相关工作的用途，不罗列与本篇无关的临床/产业免责声明。

## 背景搜索与交接

最多解决1–3个具体背景问题，如前序做法、基线含义、团队公开信息。没有关键缺口就零搜索，不能为了填栏目生成领域百科。复用已有来源，不靠模型记忆声称最新进展、原创性或行业共识。
搜索片段由宿主登记后，通过get_production_context和read_evidence取得真实ID/窗口。已支持背景放作者底稿background（kind=background），来源和范围随包交接；它与主论文核心findings分开。未回答问题保留用途和下一步，不把技术失败写成不存在。
研究结果通过save_writing_research保存后继续写作；不另排理解或背景任务。

## 提交前自查

- 非本小领域的研究者能否从解释中读懂问题和做法，术语是否有必要的短解释？
- 是否仅复述“提出某模型，全面提升性能”，却没解释关键变化？若是，重写已有解释，不增加栏目。
- 每条结果是否保留必要条件？是否把作者主张写成独立确认，把可能用途写成已实现？
- 通过save_writing_research保存理解与证据；阅读记录和结构通过不代表科学结论已获验证。
